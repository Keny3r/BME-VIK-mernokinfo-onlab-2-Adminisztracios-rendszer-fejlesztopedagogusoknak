## 1. Kell-e külön telepíteni az ASP.NET-et?

Ha a **.NET SDK** telepítve van, ASP.NET Core-projektet általában máris tudsz készíteni. PowerShellben ellenőrizd:

```powershell
dotnet --list-sdks
dotnet new list web
```

Ha az első parancs nem sorol fel SDK-t, hanem csak a `dotnet` futtatókörnyezet van meg, telepítsd a **.NET SDK-t** a [hivatalos .NET letöltési oldalról](https://dotnet.microsoft.com/download). Nem külön „ASP.NET-telepítőt” kell keresned. Ha van SDK, előbb próbáld ki az alábbiakat.

## 2. Hello world ASP.NET Core-ban

A terminálban, abban a mappában, ahol a projektet szeretnéd:

```powershell
dotnet new web -n HelloWeb
cd HelloWeb
dotnet run
```

A létrejött `Program.cs` tartalma legyen:

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", () => "Hello, world!");

app.Run();
```

Indítás után a terminál kiír egy címet, például `http://localhost:5xxx`. **A ténylegesen kiírt címet** nyisd meg böngészőben; ott megjelenik a `Hello, world!`. A szervert `Ctrl+C`-vel állíthatod le.

## 3. ORM: a következő lépés

Ha a hello world működik, az EF Core SQL Server-csomagjai így adhatók hozzá:

```powershell
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Design
dotnet tool install --global dotnet-ef
```

A csomagok és a `dotnet-ef` **főverzióját a projekt célkeretrendszeréhez kell igazítani** (ezt a `HelloWeb.csproj` `TargetFramework` sora mutatja); ezért az ORM beállítása előtt érdemes megnézni, milyen SDK-val és célkeretrendszerrel jött létre a projekt.

**Javasolt sorrend:** hello world → kapcsolat a már működő lokális MSSQL-hez → első EF Core modell és migráció → csak utána döntés a Dockerre váltásról. Így a konténerizálás nem akadályozza a határidős feladatokat.

Ha az MSSQL már telepítve van, **nem kell új SQL Server-példányt létrehoznod**. Ehhez a projekthez általában egy **új adatbázist** hozunk létre a meglévő szerveren. Az alábbi példa EF Core-ral ezt az adatbázist az első migráció futtatásakor hozza létre.

## 1. Derítsd ki a szerver nevét

Ha SQL Server Management Studio (SSMS) segítségével csatlakozol, a bejelentkezési ablak **Server name** mezőjében lévő nevet használd. Gyakori értékek:

- `localhost` – alapértelmezett SQL Server-példány;
- `localhost\SQLEXPRESS` – SQL Server Express;
- `(localdb)\MSSQLLocalDB` – LocalDB.

Windows alatt a szolgáltatások neve is segíthet. PowerShellben:

```powershell
Get-Service 'MSSQL*'
```

A `MSSQLSERVER` az alapértelmezett, a `MSSQL$SQLEXPRESS` egy `SQLEXPRESS` nevű példányra utal. **Először SSMS-ben próbálj csatlakozni Windows Authenticationnel**; ha ott sikerül, ugyanazt a szervernevet használjuk a kódban.

## 2. Add hozzá az EF Core-t a próba projekthez

A projekt mappájában:

```powershell
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Design
dotnet tool install --global dotnet-ef
```

Ha a csomagtelepítés célkeretrendszer-kompatibilitási hibát ad, **ne módosítsd találomra a projektet**: nézd meg a `.csproj` fájlban a `TargetFramework` értékét. A csomagok és a `dotnet-ef` megfelelő főverzióját ahhoz kell választani.

## 3. Állítsd be a kapcsolatot

Az `appsettings.json` fájlba tedd be a `ConnectionStrings` részt. **A szervernevet cseréld arra, amivel SSMS-ben sikerült csatlakoznod.**

Alapértelmezett példány esetén:

```json
{
  "ConnectionStrings": {
    "Default": "Server=localhost;Database=HelloWebDb;Trusted_Connection=True;TrustServerCertificate=True"
  }
}
```

`SQLEXPRESS` esetén a JSON-ban a fordított perjelet duplázni kell:

```json
{
  "ConnectionStrings": {
    "Default": "Server=localhost\\SQLEXPRESS;Database=HelloWebDb;Trusted_Connection=True;TrustServerCertificate=True"
  }
}
```

Az `appsettings.json` többi meglévő beállítását tartsd meg. A `Trusted_Connection=True` a **saját Windows-fiókoddal** kapcsolódik. A `TrustServerCertificate=True` helyi fejlesztéshez kényelmes; éles rendszerben a tanúsítványkezelést külön kell beállítani.

## 4. Készíts egy minimális modellt és végpontot

A `Program.cs` tartalma lehet például:

```csharp
using Microsoft.EntityFrameworkCore;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(
        builder.Configuration.GetConnectionString("Default")));

var app = builder.Build();

app.MapGet("/", () => "Hello, world!");

app.MapGet("/todos", async (AppDbContext db) =>
    await db.Todos.AsNoTracking().ToListAsync());

app.Run();

public class AppDbContext(DbContextOptions<AppDbContext> options)
    : DbContext(options)
{
    public DbSet<Todo> Todos => Set<Todo>();
}

public class Todo
{
    public int Id { get; set; }
    public string Title { get; set; } = "";
}
```

## 5. Hozd létre az adatbázist migrációval

A projekt mappájában:

```powershell
dotnet ef migrations add InitialCreate
dotnet ef database update
dotnet run
```

Ha a Windows-fiókodnak van jogosultsága adatbázist létrehozni, a `database update` létrehozza a `HelloWebDb` adatbázist és benne a `Todos` táblát. Ha **adatbázis-létrehozási jogosultság** miatt áll meg, hozd létre az üres `HelloWebDb` adatbázist SSMS-ben, majd futtasd újra a `dotnet ef database update` parancsot.

Végül a terminálban kiírt címen nyisd meg a **`/todos`** útvonalat. Az üres `[]` válasz jó jel: az alkalmazás elérte az adatbázist, és lekérdezte az egyelőre üres táblát.

Itt a `HelloWebDb` **adatbázis** neve. Ez kezdetben még nem feltétlenül létezik: a `dotnet ef database update` létrehozhatja, ha a Windows-fiókodnak van hozzá jogosultsága. A **táblát** (`Todos`) az EF Core modell és a migráció határozza meg, nem a connection string.

Az `InitialCreate` **nem beépített parancs**. Ebben a sorban:

```powershell
dotnet ef migrations add InitialCreate
```

a `dotnet ef migrations add` a parancs, az `InitialCreate` pedig **az általad választott migrációnév**. Magyarul nagyjából „kezdeti létrehozás”. Nevezhetnéd például `ElsoMigracio`-nak is.

A két lépés különbözik:

1. `dotnet ef migrations add InitialCreate` – létrehozza a migráció **kódfájljait** a projektben a jelenlegi modellek alapján.
2. `dotnet ef database update` – **végrehajtja** a még nem alkalmazott migrációkat az adatbázison, így létrehozza a szükséges táblákat.

Tehát nem kell előre kézzel létrehoznod a `Todos` táblát. Az adatbázist is rábízhatod a második parancsra, amennyiben megvan hozzá a jogosultságod.

A Blazor-komponens meghívhat egy szerveroldali szolgáltatást, az pedig az EF Core-t. API-végpontot akkor készítünk, ha más kliensnek is el kell érnie a funkciót.

## Javasolt kiinduló struktúra

```text
HelloWeb/
├── Program.cs
├── appsettings.json
├── Data/
│   ├── AppDbContext.cs
│   └── Migrations/           # később az EF migrációk
├── Models/
│   └── Todo.cs
├── Services/
│   └── TodoService.cs
├── Endpoints/
│   └── TodoEndpoints.cs      # csak ha API is kell
└── Components/               # amikor Blazor is bekerül
    └── Pages/
        └── Todos.razor
```

Lehet több modellt egy fájlba tenni, de **általában egy önálló osztály egy fájlban** áttekinthetőbb. Pár soros, szorosan összetartozó típusnál nem tilos a közös fájl. A cél nem egy merev szabály követése, hanem hogy megtaláld, amit keresel.

A felelősségek így válnak szét:

- `Models/Todo.cs`: milyen adatot tárolunk.
- `Data/AppDbContext.cs`: EF Core-táblák és adatbázis-beállítások.
- `Services/TodoService.cs`: az alkalmazás műveletei, például teendők listázása.
- `Endpoints/TodoEndpoints.cs`: HTTP API, **ha szükséges**.
- `Components/Pages/Todos.razor`: a Blazor-felület.
- `Program.cs`: regisztrációk és az alkalmazás összekötése; ne ide kerüljön minden üzleti logika.

Például a mostani demó `Todo` osztályát átteheted a `Models/Todo.cs` fájlba. Ha a projekt neve `HelloWeb`, akkor:

```csharp
namespace HelloWeb.Models;

public class Todo
{
    public int Id { get; set; }
    public string Title { get; set; } = "";
}
```

Az `AppDbContext` pedig a `Data/AppDbContext.cs` fájlba kerülhet:

```csharp
using HelloWeb.Models;
using Microsoft.EntityFrameworkCore;

namespace HelloWeb.Data;

public class AppDbContext(DbContextOptions<AppDbContext> options)
    : DbContext(options)
{
    public DbSet<Todo> Todos => Set<Todo>();
}
```

A `Program.cs`-ben ezek után az osztályokra a megfelelő `using` sorokkal hivatkozol.

## Hová kerül a lekérdezés?

Érdemes a Blazor és az esetleges API közé egy közös alkalmazásszintű szolgáltatást tenni:

```csharp
using HelloWeb.Data;
using HelloWeb.Models;
using Microsoft.EntityFrameworkCore;

namespace HelloWeb.Services;

public class TodoService(IDbContextFactory<AppDbContext> dbFactory)
{
    public async Task<List<Todo>> GetAllAsync()
    {
        await using var db = await dbFactory.CreateDbContextAsync();

        return await db.Todos
            .AsNoTracking()
            .ToListAsync();
    }
}
```

Ezt a `Program.cs`-ben regisztráljuk:

```csharp
builder.Services.AddDbContextFactory<AppDbContext>(options =>
    options.UseSqlServer(
        builder.Configuration.GetConnectionString("Default")));

builder.Services.AddScoped<TodoService>();
```

**Miért factory?** A későbbi interaktív, szerveren futó Blazor-komponenseknél egy felhasználói kapcsolat tovább élhet, mint egy szokásos HTTP-kérés. Nem szeretnénk ugyanazt az EF `DbContext` példányt hosszú ideig megtartani; műveletenként létrehozzuk és lezárjuk.

Az API-végpont ezután csak vékony HTTP-réteg lehet:

```csharp
using HelloWeb.Services;

namespace HelloWeb.Endpoints;

public static class TodoEndpoints
{
    public static IEndpointRouteBuilder MapTodoEndpoints(
        this IEndpointRouteBuilder app)
    {
        app.MapGet("/api/todos",
            (TodoService todos) => todos.GetAllAsync());

        return app;
    }
}
```

A `Program.cs`-ben:

```csharp
app.MapTodoEndpoints();
```

A szükséges `using HelloWeb.Endpoints;` sort is add hozzá. Ha később **nincs szükség API-ra**, az `Endpoints` mappa és ez a végpont egyszerűen elhagyható; a `TodoService` megmarad.

## Hogyan illeszkedik ide a Blazor?

Először választani kell a Blazor működési módjai között. A mi jelenlegi MSSQL + EF Core felállásunkhoz **az interaktív, szerveren futó Blazor** a legegyszerűbb indulás:

```text
Böngésző
   ↓
Blazor-komponens a szerveren
   ↓
TodoService
   ↓
EF Core
   ↓
MSSQL
```

Egy `Todos.razor` komponens közvetlenül használhatja a szolgáltatást:

```razor
@page "/todos"
@rendermode InteractiveServer
@inject TodoService Todos

<h1>Teendők</h1>

@if (items is null)
{
    <p>Betöltés...</p>
}
else
{
    <ul>
        @foreach (var item in items)
        {
            <li>@item.Title</li>
        }
    </ul>
}

@code {
    private List<Todo>? items;

    protected override async Task OnInitializedAsync()
    {
        items = await Todos.GetAllAsync();
    }
}
```

Ehhez a Blazor-projekt megfelelő inicializálása és a típusok importálása is kell; a fenti fájl a **komponens és a szolgáltatás kapcsolatát** mutatja, nem önmagában egy teljes Blazor-telepítési útmutató.

Fontos különbség: ha később **WebAssemblyben, a böngészőben futó** komponenst választunk, az nem kapcsolódhat közvetlenül MSSQL-hez. Akkor kell egy szerveroldali API, amit a böngésző HTTP-n hív.

**Gyakorlati javaslatom:** most bontsuk szét a működő demót `Models` / `Data` / `Services` részekre, és hagyjuk meg a `/api/todos` végpontot ellenőrzésre. Amikor a Blazort bevezetjük, ugyanazt a `TodoService`-t használja majd a komponens is. Így nem kell előre eldöntenünk, hogy hosszú távon szükség lesz-e publikus API-ra.
